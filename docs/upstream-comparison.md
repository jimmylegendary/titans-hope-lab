# Upstream lineage와 이 snapshot의 차이

이 monorepo는 별도 환경과 별도 구현을 가진 두 code snapshot을 묶습니다. 하나를 다른 하나의 fork나 공동 architecture로 설명하지 않습니다. Provenance와 원 license는 [THIRD_PARTY_NOTICES.md](https://github.com/jimmylegendary/titans-hope-lab/blob/main/THIRD_PARTY_NOTICES.md), upstream 식별자는 [provenance.json](https://github.com/jimmylegendary/titans-hope-lab/blob/main/docs/provenance.json), 가져온 runtime 파일의 해시는 [source-integrity.json](https://github.com/jimmylegendary/titans-hope-lab/blob/main/artifacts/source-integrity.json)에 있습니다.

## 코드 출처와 snapshot 경계

| 프로젝트 | 직접 기반과 역할 | 현재 snapshot에 추가된 실행·검증 경로 |
|---|---|---|
| Titan-Llama | [Sarah Pan의 Titans PyTorch fork, `c60b4ef`](https://github.com/sarahpannn/titans-pytorch/tree/c60b4efaa3a3c6df4deebd57cbccf75947b87cad)은 arXiv Titan-Llama가 직접 링크한 retrofit 코드다. 이 fork의 일반 Titans core는 [lucidrains/titans-pytorch, `1d40c445`](https://github.com/lucidrains/titans-pytorch/tree/1d40c445fa1794fb28582c721786482b5b683e47)를 계승한다. | HF Llama layer replacement와 NMM path의 freeze/scratch/missing-path runtime 문제를 바로잡고, pretrained freeze·gradient·cache decode를 확인하는 bounded tests와 tiny synthetic CPU smoke를 더했다. 1B model check는 별도 선택 실행이다. |
| HOPE | [smallhours19/nested-learning-hope, `5fdbe522`](https://github.com/smallhours19/nested-learning-hope/tree/5fdbe522a9b10279661530aea5bf8dd7f9b4c180)의 matrix/deep memory, CMS, declared deviations와 stability catalog를 출처로 한다. | CPU tiny byte train/eval/generate/resume CLI, optimizer/RNG checkpoint, Linux x86_64 CPU lock, aligned streaming·gradient·state·causality tests를 추가했다. main loss와 activation-checkpoint side graph의 all-ignored partial tail을 valid-token count로 안정화했다. |

`provenance.json`의 validated pre-publication SHA는 이 monorepo 안의 확인된 local snapshot을 식별하며, upstream 원격 저장소에서 그대로 fetch할 수 있는 commit이라고 표시하지 않습니다. 실제 upstream commit과 local snapshot ID는 provenance 자료에서 별도 필드로 관리합니다.

## Titans 계보에서 참고할 점

Paper-linked Sarah Pan fork는 adapter 경로의 출처이고, lucidrains 저장소는 Titans MAC/MAG/MAL 및 chunk state API의 보다 일반적인 core reference다. 두 저장소는 독립적인 저자 공개 Titans reproduction으로 두 번 세지 않습니다. [omkarghugarkar007의 implementation](https://github.com/omkarghugarkar007/titans-pytorch-unofficial-implementation/tree/6e4728b15706aa862e022ae6304b8b0837544697)은 sequential/chunk recurrence와 causality 검사의 간결한 참고다. [mukktinaadh/titans-repro](https://github.com/mukktinaadh/titans-repro/tree/417da401589d7f9eec8120a57cc0e0abbca41e57)는 더 많은 테스트와 toy logs를 두지만 저장소 license가 확인되지 않고, 그 결과는 paper-scale 성능 근거가 아니다.

정적 감사에서 [Aedelon/titans-pytorch-mlx](https://github.com/Aedelon/titans-pytorch-mlx/tree/0dc7a4d2829df55d221f67bf56c0603e9ac7c6f4)의 sequence-averaged gate와 detached memory-state 경로, [ZoonSoftware/titans-memory](https://github.com/ZoonSoftware/titans-memory/tree/35d4712290ca93534fc3fc974d3174ddc6a4f240)의 no-decay 분기, [pafos-ai/titans-trainer](https://github.com/pafos-ai/titans-trainer/tree/63d86f8b4140ce09130a97155cf5f399380e32cf)의 local MSE objective/state semantics가 upstream 비교에서 구분된다. 이는 정적 code finding이며 실행 결과라고 주장하지 않는다. [Coalyx/OpenTitans](https://github.com/Coalyx/OpenTitans/tree/a329ee6dcca8de8d3bdc7d8bbedc430f71398c8d)는 여러 memory family를 비교하는 catalog로 참고하되 independent algorithm count에 그대로 더하지 않는다.

## HOPE 구현 후보와 선언된 차이

[kmccleary3301/nested_learning](https://github.com/kmccleary3301/nested_learning/tree/56463f3853552f17791bc10a40c534864724d614)은 fast state와 outer/meta-gradient 분리, CMS/M3 tests를 포함한 넓은 component reference다. [obekt/HOPE-nested-learning](https://github.com/obekt/HOPE-nested-learning/tree/25bdd70c33d0162216725b1cd7a1e2605ba315be)은 chunk/update 테스트와 공개된 run/probe logs가 있지만 root LICENSE 파일이 확인되지 않았다. [Lazarus-931/Nested_Learning](https://github.com/Lazarus-931/Nested_Learning/tree/a38b34e0e9991ef2b6368c008683e58de0ab0a00)는 self-generated targets를 포함한 self-modifying core 참고이고, 확인한 CMS path는 task-loss gradient accumulation과 다르다. [erikl2/nested-learning](https://github.com/erikl2/nested-learning/tree/fbc3256cdd6dc45f3278197b1db7635430a71b3a)는 별도 DMGD optimizer 후보지만 그 저장소의 generic training path가 cadence-aware CMS trainer를 호출하는 것은 확인하지 못했다. [FrankFacundo/nested_learning](https://github.com/FrankFacundo/nested_learning/tree/58043ec2f2a2ad0c1229f42ba8a1e1b0e566017e)는 self-generated state와 M3 조각을 갖지만 CMSLevel은 task-loss-trained MLP chain과 다르고 저장된 run metrics는 step 0 한 줄이다. [Abraheem13/HOPE-PHY](https://github.com/Abraheem13/HOPE-PHY/tree/f44b346483ee3809d3d0e3e903c3646044d084ff)는 6G prediction 응용이며 language-model baseline으로 섞지 않는다.

이 snapshot도 paper-exact 전체 HOPE라고 부르지 않습니다. Matrix-memory Eq. 88–90 chunk path에는 순차 recurrence 비교가 있지만, deep Eq. 91 경로는 chunk-start retrieval을 사용합니다. CMS level learning rate와 firing phase, projection-memory suffix factor, query adaptivity 등은 원문과 구분해 [DEVIATIONS.md](https://github.com/jimmylegendary/titans-hope-lab/blob/main/implementations/hope/docs/DEVIATIONS.md)에 남아 있습니다. [model.py](https://github.com/jimmylegendary/titans-hope-lab/blob/main/implementations/hope/hope/model.py#L663-L739)의 all-ignored tail 보완은 valid-token count가 0일 때 main loss와 checkpoint side loss를 finite zero로 유지하는 runtime safety fix다. Regression은 두 memory mode에서 side loss·gradient·state를 확인한다. 해당 경로에서 이전에 NaN gradient/state가 관측됐다고 주장하지 않는다.
